02 · Visual guide

How DBSCAN makes a cluster

DBSCAN means Density-Based Spatial Clustering of Applications with Noise. It groups points through local density. It does not need the number of clusters in advance and can find curved shapes.

1 · Choose a point

Look inside a circle of radius ε around it.

2 · Count neighbors

MinPts includes the point itself.

3 · Grow from core

A core point has enough neighbors. Add them to a queue and explore.

4 · Mark the rest

Nearby non-core points become border points. Isolated points are noise.

Core, border and noise

CoreBorderNoise

Cluster expansion

ε (epsilon) is the neighborhood radius. MinPts is the minimum neighborhood size, counting the point itself. A core point has at least MinPts points in its ε-neighborhood. A border point is within ε of a core point but does not meet MinPts itself. Noise is not density reachable from any core point.

Start at an unvisited core point. Add its neighbors to a queue. When a queued point is also core, add its neighbors. Stop when the queue is empty. A border point joins but does not expand the cluster.

distance(p,q)² ≤ ε²
core(p) ⇔ |Nε(p)| ≥ MinPts

A point first marked noise may later be reached by a core point and join as a border point.

Start with the idea of a data point

A data point is one observation described by numbers. On a map, those numbers could be an east–west coordinate and a north–south coordinate. In our demo, every dot has two numbers, x and y. Nearby dots have similar positions. A cluster is a group of observations that the algorithm puts together.

Machine learning includes methods that discover patterns from data. DBSCAN is an unsupervised method: we give it points without correct cluster labels, and it discovers groups using a density rule. Density simply means how many points lie in a small area.

Two settings define “dense enough”

ε: how far do we look?

Read ε as “epsilon.” It is a distance, not a number of neighbors. Draw a circle of radius ε around point p. Every point inside or exactly on that circle belongs to p’s neighborhood. We count p itself, too.

A small ε creates smaller neighborhoods, often leaving more noise. A larger ε can connect previously separate groups. In this demo coordinates are between 0 and 1, so ε = 0.05 means 5% of one coordinate axis.

MinPts: how many are enough?

MinPts is a whole-number threshold. If MinPts = 4, p needs itself plus at least three other observations within ε to be a core point.

Raising MinPts makes the density requirement stricter. The same point can change from core to border or noise when you change the settings. Duplicate observations count separately.

What the three point types mean

  • Core: has enough neighbors to start or continue growing a cluster.
  • Border: does not have enough neighbors itself, but is within ε of a core point. It joins that cluster without growing it further.
  • Noise: is neither core nor close enough to any core point to join. Noise does not automatically mean an error; it means the density rule did not assign a cluster.

A concrete example

Take ε = 1 and MinPts = 4. Let A=(0,0), B=(0.4,0), C=(0.2,0.4), D=(-0.4,0.2), E=(1.3,0), and N=(3,1). A, B, C and D are all within distance 1 of one another, so each has at least four neighbors including itself. They are core points. E is 0.9 from B but has only itself and B in its neighborhood, so E is border. N has no core neighbor and remains noise.

Walking through a complete run

  1. Mark every point unvisited. Pick the first unvisited point and find its neighbors.
  2. If it has fewer than MinPts neighbors, mark it noise for now and continue to another point.
  3. If it is core, start a cluster and put its neighbors in a queue: a waiting list of points to process.
  4. Take the next queued point. Assign it to the cluster if it has not already joined one. If it is unvisited, inspect its neighborhood.
  5. If that point is also core, add its neighbors to the queue. Avoid adding the same point repeatedly within this cluster.
  6. When the queue is empty, the cluster is complete. Continue until no unvisited points remain.

Only chains of core points spread a cluster. This is why a cluster can bend around a curve, and why a border point cannot connect two otherwise separate core groups. A point marked noise early can later become border. A border point beside two clusters may join whichever reaches it first; our two implementations keep the same traversal order.

How the distance check works

Squared distance = (x₁ − x₂)² + (y₁ − y₂)²
Neighbors if squared distance ≤ ε²

For p=(2,3) and q=(2.3,3.4), the squared distance is 0.3² + 0.4² = 0.25. With ε=0.5, ε² is also 0.25, so q is a neighbor. Comparing squares avoids taking a square root without changing the answer.

Distances only make sense when coordinate scales are meaningful. If one feature is measured in thousands and another in fractions, the larger scale can dominate. Real datasets may need feature scaling before clustering. DBSCAN can also struggle when different clusters have very different densities.

Definition and expansion rules: Ester et al., original DBSCAN paper, sections 3–4.

03 · Why performance changes

The repeated neighborhood search causes the quadratic checks.

Traditional scan

n query points × n distance checks = n²

For this straightforward implementation, each region query scans all n points. Up to n points are queried, so the distance checks grow as n². At n=1,000, one full scan per point gives about 1,000,000 distance checks. Doubling n makes about four times as many checks.

Spatial grid

Build index: O(n)
Query work: local candidates

When points are spread out and each query sees a bounded number of nearby candidates, total work is expected near O(n). If the data is dense or ε is large, each query can still examine Θ(n) points, so total work can remain Θ(n²).

Honest claim: the grid reduces work on suitable data. It does not guarantee O(n) for every dataset. Our queue implementation now uses a reusable stamp array to avoid resetting n flags for every new cluster.

Spatial filtering keeps DBSCAN exact

With square cells of side ε, a point can only have neighbors in its own cell or one of the eight adjacent cells in 2D. The grid finds candidates; an exact squared-distance check decides which candidates are true neighbors.

cell(x,y) = (floor(x/ε), floor(y/ε))
search: 3 × 3 neighboring cells

Using floor matters for negative coordinates. True neighbors are never skipped by the nine-cell lookup.

What does time complexity measure?

Let n mean the number of input points. Time complexity describes how the amount of work grows as n increases. It does not predict an exact number of seconds. Two computers can run the same algorithm at different speeds while following the same growth pattern.

O(n), or linear growth, means work is bounded by a constant multiple of n for sufficiently large n. O(n²), or quadratic growth, grows with n multiplied by itself. Θ describes a tight growth rate: both upper and lower bounds have that order.

Where our speedup comes from

The baseline asks each point about every other point, even when most are very far away. Our version first organizes points into grid cells. Each query looks up nine cell locations, then checks only the points those cells contain. It still uses the exact same distance formula and density threshold.

Suppose a query has 1,000 possible points but only 10 local candidates. The baseline performs 1,000 distance checks; the grid version performs 10, plus the cost of finding those cells. Avoiding the other 990 comparisons is the main saving.

When can the total be expected O(n)?

We assume fixed two-dimensional data, a bounded number of local candidates as the dataset grows, and well-distributed hash buckets with bounded expected collision overhead. We also use one stamp array, initialized once. Under these conditions, indexing, neighborhood work and cluster expansion together are expected linear.

Our code sorts each neighbor list to preserve input order. A list of k neighbors has a general sorting bound O(k log k). If k stays bounded, this is bounded work per query too. If neighborhoods grow, sorting and expansion must also be counted.

Why nine cells does not always mean constant work

Nine empty cells are cheap. Nine cells containing nearly all n points are expensive. If every point lies within ε of every other, our explicit neighborhood queries perform n² distance checks. A large ε, a dense cloud, or bad hash collisions can remove the advantage. This is a limitation of this implementation, not a proof that every possible DBSCAN algorithm must always enumerate all pairs.

Putting more points into the same fixed area often increases density. To study linear scaling, grow the spatial area as n grows so the local workload stays comparable. Also report dense cases rather than selecting only favorable data.

Space complexity means memory growth

The main versions keep point coordinates, labels, a queue and temporary neighbors. The grid adds buckets and one linked node per point. These structures together use O(n) peak auxiliary space. A program can take quadratic time while using only linear memory because it repeats calculations without storing every answer.

The optional DSU version stores every neighborhood. If each of n points has n neighbors, those lists contain n² entries, so memory can become quadratic.

Reading our measurements correctly

One distance check is one evaluation of whether a pair is within ε. The counter does not include hashing, sorting or queue management. The timer includes algorithm setup and execution, including grid construction, but excludes HTTP transfer and drawing. We warm up both algorithms, alternate their order and report the median of three measured runs. A speed ratio above 1 means the grid was faster in that measurement; below 1 means it was slower.

04 · Data structures

Each structure removes a different kind of work.

Spatial hash table

Maps each grid-cell coordinate to a bucket. It narrows a query to nearby cells rather than all n points.

Linked collision chains

Each bucket stores nodes in a singly linked list. Full cell coordinates filter hash collisions.

Queue

A list with a moving head expands clusters in first-in, first-out order without shifting elements.

Labels and stamp array

Track unvisited, noise and cluster membership. A cluster ID stamp avoids clearing an n-sized array for every cluster.

Auxiliary space for the grid + queue version is O(n). The optional DSU implementation caches neighborhoods and can use O(n²) space in dense data.

What is a data structure?

A data structure is a way of arranging information so certain operations are efficient. Imagine finding a book: an unsorted pile requires searching through everything, while shelves organized by category let you narrow the search. Our structures organize points, pending work and processing state.

1. Spatial hash table: find the relevant area

Divide the plane into squares of side ε. For p=(2.2,1.4) and ε=1, the cell coordinate is (2,1). The floor operation rounds down: floor(-0.2)=-1. A hash function converts this pair of integers into an index in an array of buckets.

point (2.2, 1.4) → cell (2, 1) → hash → bucket

Insert every point once. To query p, look up the cells whose x indices are 1,2,3 and y indices are 0,1,2. Every true neighbor must lie in those nine cells because a point at distance at most ε cannot differ by more than ε on either axis. The square of candidate cells is larger than the circle, so some candidates still fail the distance check.

2. Linked lists: keep hash collisions safe

Different cell coordinates may produce the same bucket index. This is called a hash collision. It does not mean the points occupy the same cell. Our bucket contains a chain of nodes, and each node stores the full cell coordinates, a point index and a reference to the next node.

bucket → [cell (2,1), point 7] → [cell (8,4), point 9] → end

While traversing the chain, compare the stored coordinates with the requested cell. Only matching nodes become candidates. Prepending a node is O(1). Traversing a bucket costs O(L), where L is its chain length. Good hash distribution helps keep unrelated collision work small, but a crowded cell can still have a long chain.

3. Queue: explore a cluster in order

A queue works like a line at a shop: the first item added is the first processed. Our code uses a Python list with a head index. Appending an item is amortized O(1), meaning occasional list resizing averages out over many additions. Reading queue[head] and increasing head is O(1).

queue = [B, C, D], head = 0
Process B, discover E
queue = [B, C, D, E], head = 1
Next point: C

We do not repeatedly remove index zero, which would shift the remaining items. Core points add neighbors to the queue. Border points receive their cluster label without extending the search.

4. Arrays: remember what happened

An array lets us access an entry by its point index. labels[i] stores -2 for unvisited, -1 for noise, or a nonnegative cluster ID. Reading and writing a fixed index takes O(1).

The stamp array records which cluster has already queued a point. Initially every entry is -1. When cluster 3 queues point 8, stamp[8] becomes 3. If cluster 3 encounters it again, the matching stamp prevents a duplicate queue entry. A later cluster uses a different stamp, so we do not clear the whole array.

This matters with many small clusters: clearing n flags for each of K clusters costs O(nK). If K grows with n, that alone can be quadratic. Initializing stamps once removes that repeated full-array work.

Optional: disjoint-set union (DSU)

DSU tracks which items belong to the same group. find identifies a group representative; union merges two groups. Our optional implementation uses DSU to connect neighboring core points, then attaches border points. Path compression shortens future paths to a representative, while union by rank keeps trees shallow. This variant is separate from the main queue algorithm, and its cached neighbor lists can use quadratic memory.

Together: the grid finds candidates, linked chains resolve collisions, the queue controls exploration, and labels plus stamps prevent repeated work.

05 · Reading the results

Compare more than the stopwatch.

Accuracy here means agreement between two implementations of the same DBSCAN definition, not accuracy against human-labeled truth. ARI is permutation-invariant. A score of 1 indicates equivalent partitions. The demo also checks exact label equivalence for a direct correctness signal.

For a fair report, run several times with the same generated points. Include sparse, clustered, dense and many-small-cluster cases. Report median time and distance checks. The optimized version may be slower when the grid cannot prune candidates.
